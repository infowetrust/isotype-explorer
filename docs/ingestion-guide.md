# Ingestion Guide

This guide covers adding new works and figures to the Isotype Explorer from:

- WEBP derivatives already prepared for the site.
- A Google Sheet with `works`, `figures`, and `captions` tabs.

The site build reads CSV exports from `data-source/`, generates JSON in `public/data/`, and expects image files in `public/webp/`.

## Expected Filenames

Every figure id in `figures.csv` must match the image filenames exactly.

For figure id:

```text
w0012-p0003-f00
```

the site expects:

```text
public/webp/thumbs/w0012-p0003-f00_h0500.webp
public/webp/views/w0012-p0003-f00_h2400.webp
```

The image paths are generated by `scripts/build_data.py`; they are not read from the Google Sheet.

## Step 1: Export Google Sheet Tabs

Download each tab as CSV and put the full tab exports here:

```sh
/Users/rja19/Documents/github/isotype-charts/data-source/works.csv
/Users/rja19/Documents/github/isotype-charts/data-source/figures.csv
/Users/rja19/Documents/github/isotype-charts/data-source/captions.csv
```

Use the full current tabs, not only newly added rows. The builder creates the complete site JSON from these files each time.

Required/important columns:

- `works.csv`: `work_id`, `title`; plus metadata such as `year`, `series`, `language`, `authors`, `publisher`.
- `figures.csv`: `figure_id`; plus metadata such as `work_id`, `figure_title`, `types`, `features`, `colors`, `themes`.
- `captions.csv`: `figure_id`, `caption`.

The scripts normalize many header variants, but these names are the clearest current convention.

## Step 2: Copy WEBPs Into The Site

If the WEBPs already exist in the source workspace, copy thumbs and views into the site:

```sh
cd /Users/rja19/Documents/github/isotype-charts
rsync -av /Users/rja19/Documents/PROJECTS/2026-book_explorer/w0012/04-webp/thumbs/*.webp public/webp/thumbs/
rsync -av /Users/rja19/Documents/PROJECTS/2026-book_explorer/w0012/04-webp/views/*.webp public/webp/views/
```

Replace `w0012` with the work folder you are adding.


## Step 3: Build Site Data

From the site repository:

```sh
cd /Users/rja19/Documents/github/isotype-charts
python3 scripts/build_data.py
```

This writes:

```text
public/data/works.json
public/data/figures.json
```

Read any warnings. The important ones are usually:

- A figure references a `work_id` that is missing from `works.csv`.
- A caption references a `figure_id` that is missing from `figures.csv`.
- A multi-type figure has unscoped or missing features.

You can also build from temporary CSV paths:

```sh
python3 scripts/build_data.py \
  --works /path/to/works.csv \
  --figures /path/to/figures.csv \
  --captions /path/to/captions.csv
```

## Step 4: Update OCR

OCR is stored in:

```text
public/data/ocr.json
```

Run OCR after adding new figures:

```sh
python3 scripts/ocr_views.py
```

Use `--force` if an image changed and you want to regenerate existing OCR records:

```sh
python3 scripts/ocr_views.py --force
```

For a quick trial:

```sh
python3 scripts/ocr_views.py --limit 5
```

Tesseract is required:

```sh
brew install tesseract
```

If you want OCR to prefer original PNGs from the source workspace when available:

```sh
python3 scripts/ocr_views.py --png-root /Users/rja19/Documents/PROJECTS/2026-book_explorer
```

## Step 5: Optional AI Descriptions

Descriptions are stored in:

```text
public/data/descriptions.json
```

This is optional and slower. It requires Ollama running locally with the configured models:

```sh
ollama serve
ollama pull llava:7b
ollama pull llama3.1:8b
```

Trial run:

```sh
python3 scripts/describe_views_ollama.py --limit 5
```

Full run:

```sh
python3 scripts/describe_views_ollama.py
```

Regenerate existing descriptions only when intended:

```sh
python3 scripts/describe_views_ollama.py --force
```

## Step 6: Validate

Run the fast data and unit checks:

```sh
npm run test
```

Run browser smoke tests when image paths, layout, search/filter behavior, or lightbox behavior changed:

```sh
npm run test:e2e
```


## Step 7: Review In Browser

Start the local site:

```sh
npm run dev
```

Then manually verify:

- The new work appears in filters/publications.
- New cards show titles/captions and thumbnail images.
- Search finds new figures by title, caption, and OCR text.
- The lightbox opens from a new card and shows the full view image.
- Direct links work for known figure ids, for example `/?id=w0012-p0003-f00`.

## Common Failure Points

- The `figure_id` in `figures.csv` does not exactly match the WEBP filename stem.
- WEBPs were left in `2026-book_explorer` and not copied into `public/webp/`.
- The Google Sheet export contains only new rows instead of the full tab.
- `captions.csv` has a `figure_id` that is not present in `figures.csv`.
- `figures.csv` has a `work_id` that is not present in `works.csv`.
- A combo figure lists multiple `types` but the `features` cell is not scoped by type. Use a pattern like `bar: stacked, horizontal; map: world`.
- `grey` is normalized to `gray`.
- `black` or `only black` becomes `onlyBlack`.
